# Контракты сервисов

Общие единицы:

- давление — **атм**;
- дебит жидкости — **м³/сут**;
- длина — **м**;
- температура — **°C**;
- обводнённость на входе — **%**;
- газовый фактор `rp` — **м³/т**.

Все ошибки валидации — HTTP 4xx и JSON-объект. Формат полей может отличаться,
но ответ не должен быть HTML или пустым телом.

У каждого расчётного сервиса одинаковый набор служебных endpoint'ов:

```http
GET /<service>/health
```

```json
{"status": "ok", "service": "ipr"}
```

- health возвращает HTTP 200 без тела запроса и без авторизации;
- поле `service` — `ipr`, `vlp` или `nodal`;
- OpenAPI: `/docs` и `/openapi.json`.

---

## 1. IPR

```http
POST /ipr/calc
Content-Type: application/json
```

Запрос:

```json
{
  "p_res": 200,
  "wct": 50,
  "pi": 1,
  "pb": 150
}
```

Ответ:

```json
{
  "q_liq": [139.98, 137.93, "...", 0.0],
  "p_wf": [1.0, 10.95, "...", 200.0]
}
```

Требования:

- ровно 21 точка;
- `p_wf` от 1 атм до `p_res`;
- `q_liq` — суммарный дебит жидкости, м³/сут;
- `q_liq >= 0`, `p_wf > 0`, без `NaN`/`Inf`;
- `q_liq` не возрастает с ростом `p_wf`;
- при `p_wf = p_res` дебит равен 0;
- при `wct = 100` — линейная модель;
- при `p_wf >= pb` — линейная модель по `pi`;
- при `wct = 0` и `p_wf < pb` — модель Вогеля.

Валидация:

- `p_res > 0`;
- `0 <= wct <= 100`;
- `pi >= 0`;
- `pb >= 0`.

OpenAPI/Swagger обязателен.

## 2. VLP

```http
POST /vlp/calc
Content-Type: application/json
```

Запрос:

```json
{
  "inclinometry": {
    "MD": [0, 1000, 1500],
    "TVD": [0, 1000, 1100]
  },
  "casing": {"d": 0.1},
  "tubing": {"d": 0.062, "h_mes": 1000},
  "pvt": {
    "wct": 50,
    "rp": 100,
    "gamma_oil": 0.8,
    "gamma_gas": 0.7,
    "gamma_wat": 1.0,
    "t_res": 90
  },
  "p_wh": 10,
  "geo_grad": 3,
  "h_res": 1500,
  "roughness": 0.0001,
  "q_max": 400,
  "points": 21
}
```

Ответ:

```json
{
  "q_liq": [0.0, 20.0, "...", 400.0],
  "p_wf": [47.48, 47.56, "...", 62.16]
}
```

Требования:

- гомогенная модель без скольжения фаз;
- гравитация + трение, без ускорения;
- коэффициент трения — Colebrook–White в итерационной форме;
- интегрирование RK45/RK23;
- участки: НКТ `0…h_mes`, ЭК `h_mes…h_res`;
- `points` точек, `q_liq` от `<= 1` до `q_max`;
- `p_wf > 0`, без `NaN`/`Inf`;
- `q_liq` строго возрастает;
- `roughness`, `q_max`, `points` — опциональные, значения по умолчанию
  `0.0001`, `400`, `21`.

Валидация:

- `MD` и `TVD` одной длины;
- `MD` строго возрастает;
- `TVD` не убывает;
- `h_mes < h_res <= max(MD)`;
- `casing.d > tubing.d`;
- `p_wh > 0`;
- `0 <= wct <= 100`;
- `roughness > 0`, `q_max > 0`, `2 <= points <= 201`.

OpenAPI/Swagger обязателен.

## 3. Nodal

```http
POST /nodal/calc
Content-Type: application/json
```

Nodal не принимает исходные данные скважины. Он принимает две готовые кривые:

```json
{
  "ipr": {
    "q_liq": [139.98, 137.93, "...", 0.0],
    "p_wf": [1.0, 10.95, "...", 200.0]
  },
  "vlp": {
    "q_liq": [0.0, 20.0, "...", 400.0],
    "p_wf": [47.48, 47.56, "...", 62.16]
  }
}
```

Ответ:

```json
[
  {"q_liq": 95.3, "p_wf": 50.1}
]
```

Требования:

- ровно одна точка пересечения;
- массив ровно из одного элемента;
- `q_liq >= 0`, `p_wf > 0`, без `NaN`/`Inf`;
- точка должна лежать на обеих кривых;
- единицы ответа совпадают с единицами входа.

Multi-intersection в рамках хакатона не требуется и не тестируется.

## 4. E2E: Petroleum Office

Полный сценарий:

```text
IPR request  → POST /ipr/calc  → IPR curve
VLP request  → POST /vlp/calc  → VLP curve
             → POST /nodal/calc → operating point
```

Для кейса Petroleum Office VLP вызывается с `roughness = 0.0006`,
`q_max = 2000`, `points = 41`.

Ожидаемая рабочая точка Petroleum Office:

- `q ≈ 5297.83 bbl/d`;
- `p ≈ 2375.79 psi`.

В единицах сервисов:

- `q ≈ 842.3 м³/сут`;
- `p ≈ 161.7 атм`.

Допуск E2E: 10% по дебиту, 5% по давлению.

## 5. Общий `input_data.json`

`examples/input_data.json` — общий пример кейса. Для прямых вызовов сервисов
используйте отдельные файлы:

- `examples/ipr_request.json`;
- `examples/vlp_request.json`;
- `examples/nodal_request.json`.

Если backend принимает общий JSON, он должен нормализовать:

- `p_res`, `pi` — верхний уровень;
- `wct` для IPR — `pvt.wct`;
- `pb` для IPR — `pvt.pb` (или верхний уровень, если так решено в вашем backend);
- VLP получает `pvt` без IPR-полей.

## 6. Слой приложения (обязателен, проверяется на защите)

`backend/`, `frontend/` и `ai_assistant/` — обязательные части системы.
Автоматическая проверка запускает только `ipr`, `vlp` и `nodal`.
Слой приложения оценивается на демо и live-защите.

- Backend — порт 8080, оркестрация, сценарии, tool layer для помощника.
- Frontend — порт 3000, дашборд и рабочая точка.
- AI-помощник — модуль backend или отдельный сервис под профилем `app`.

Для запуска полного приложения:

```bash
docker compose --profile app up -d --build
```

Для проверки расчётных сервисов:

```bash
docker compose up -d --build ipr vlp nodal
```
